Build Log
Roadmap
Aug 28, 2026
NewDaily recap email
Brand new daily-recap function, Mon-Sat 4am, opt-in per trainer via the new "⚙️ Options" toggle on the roster screen. Covers a trainer's own roster only: no-consistency-goal-set flags, persistent specific-day misses (stays flagged until actually resolved, not just "today"), goals 3-or-fewer completions from done, recheck dates coming up, and Monday-only weekly-count shortfalls for the week that just closed. Everyone else gets a consistent roster line — check-in streak, goal progress, recheck date.
NewWeekly recap rebuilt as a celebration, not a status report
Moved from Monday worst-first list to a Sunday highlight reel. Every client's whole week — both schedule types — scored as one fair completion percentage, converted to stars with real leniency at the top (90%+ still earns all 5; this is about accomplishment, not grading precision). Anyone below 60% simply isn't in the email at all — no sad stars mixed into a celebration.
FixRecheck reminders could fire after a goal was already met
Caught while sharpening the config screen's copy to match: the new daily recap's recheck flag didn't check whether the consistency goal above it had already been hit, contradicting the original design. Fixed and redeployed — a recheck only fires if there's still something left to reassess.
NewGetting Started doc: philosophy, self-signup, and the "why" behind goals
Added an upfront philosophy section (not a check-in tool, not a to-do list, why 3 dids or fewer works better), documented the self-signup flow trainers never had written down, and split the consistency-goal/recheck-date step into two clearly-reasoned points — now mirrored on the real admin/plan.html config screen too, not just the docs.
InfraEdge functions now deploy directly, no CLI needed
daily_recap_enabled column added to trainers; both recap functions deployed straight through the Supabase connector going forward, confirmed working end to end against real data before either went live.
FixArchived clients kept reappearing everywhere
The archive button, its confirmation, and the database write all worked correctly — but the code that builds every client list had archived: false hardcoded for every single client, completely ignoring the real value. Every archived client, ever, kept showing up in the roster, client counts, and the all-clients list. Fixed at the source; confirmed the fix propagates to all six places that read this field.
Aug 26, 2026
FixEvery save on any client's plan screen was silently failing
Urgent, wide-reaching bug: a migration for the recheck-cadence field was never actually run, even though other migrations from the same batch were. Every single assignment save — any item, any client — had been failing with a database error since that UI shipped, because the save always tried writing to a column that didn't exist. Also recovered one real client's dropped assignment: the edit flow closes the old row before creating the replacement, so the very first failed save had silently left them with no active assignment for that did at all. Restored with the values that were clearly intended, then verified the fix against the exact case that had failed.
FixSignup notification emails never actually worked
Chasing down a leaked test signup (an internal test's fallback request actually went through and emailed a real trainer) surfaced a deeper bug: the code that emails admins about a new signup never fetched or passed a trainer's login token in either branch — preference stated or not. Even a correctly-identified trainer's email was never going to link anywhere useful. Fixed both branches to fetch and pass real tokens.
Aug 25, 2026
NewSelf-signup wizard with real per-item configuration
Clients picking their own dids now configure each one in detail — goal, input style, schedule, and consistency target — with a live preview of the actual question exactly as it'll look on check-in day. Capped at 5 items with escalating guidance past 3, nudging toward focus over breadth. The trainer's "Complete Setup" screen now shows the client's real chosen configuration as editable cards to review and adjust, not a blank slate of hardcoded defaults — tested end to end on the live site itself, not just a sandbox copy.
FixTrainer Stats tab rebuilt, and a real regression caught mid-build
The trainer-facing Stats tab now uses the same schedule-aware white/amber/green dot-row as the roster, with numeric and text answers tucked behind an expandable dropdown — fixing a real bug where a client with zero check-in history was shown as having "missed" days before anything was even assigned to them. Along the way, an in-progress redesign was accidentally built on a copy of the app that hadn't yet received an already-shipped fix, silently reverting it — caught, reapplied, and both changes verified to coexist correctly before shipping.
Aug 21–22, 2026
NewPremier U catalog rebuilt to match report rows exactly
Overly broad groupings (one action holding 8 unrelated dids) split into precise, one-to-one matches against each row across all 5 real source documents — cross-referenced by hand, catching a wrong grouping guess (creatine and magnesium belonged with carb timing, not their own "recovery" action) and adding a real guidance field to actions themselves, so a trainer sees full context — brands, dosing — without drilling into individual items.
NewConsistency goals made unbounded, plus a separate recheck field
A goal no longer resets or penalizes someone for a gap in activity — it now counts real completions since the assignment started, however long that takes, rather than a rolling window that could quietly punish a comeback. A completely separate "check back in after N days" field was added alongside it, for periodic re-evaluation regardless of whether the goal's been hit — since "did they succeed" and "has it been a while since anyone looked" turned out to be two different questions, not one.
NewSafe preview mode for trainers
A trainer can now open a client's real check-in screen to see exactly what they'll experience, without creating real data. Genuinely safe, not just a hidden button — submission is blocked at the actual data-writing function every real check-in already funnels through, verified directly against the database after a full test run that nothing was written.
Also: MCP connectors evaluated for this project — Supabase declined for now (the manual SQL-review step has caught real problems more than once), GitHub recommended (tightly scoped, PR-based workflow) but not yet connected.
Aug 20–21, 2026
NewActions: themed goals grouping several dids together
Trainers can now assign a real, themed "action" (e.g. "Protein Intake Ramp") that groups several related dids into one pool, rather than assigning items one at a time. Includes a real accomplishment flow: a scheduled job detects when a consistency goal is met, surfacing a "⭐ Goal met" indicator to both the client and the trainer, with a genuine decision screen afterward — raise the target, or swap to something else already in the plan — that carries the goal's history forward rather than losing it.
FixA pre-existing, wider-reaching display bug
Found while building Actions, not caused by it: a misplaced closing tag meant the assigned-items list had never actually been hidden between screens for anyone, on any client, since long before this session — it just silently stayed visible behind whatever screen a trainer navigated to next. One stray tag, removed.
FixRoster misjudged days before a client's tracking began
The day-status logic never checked when an assignment actually started, so any day-of-week match got marked "Missed" even for dates before a client existed on that schedule at all. A second, related bug in the same function silently skipped "every day" schedules entirely. Both fixed and verified against two clients with different schedules and start dates.
FixAdd Client had zero org-filtering
The catalog picker pulled every item from every org regardless of context, with no concept of Actions at all. Fixed alongside two other bugs caught in the same pass: a duplicate function name silently overwriting itself (breaking the roster's own copy-link button), and dids created inline from this screen not being scoped to the right org.
Also: trainer login links with copy buttons, and admin-triggered PIN reset, added to the roster.

NewChange trainer, and library item archiving

Library items can now be archived with a real confirmation step, soft-delete throughout so client history is never lost; caught and fixed a related bug where the "assign an item" picker on a client's plan never respected the archive filter.

SecurityCheck-In Library had zero authentication
Anyone who found the URL could freely add, edit, or delete the entire catalog — including Premier U's clinical content — no login required. Closed with the same gate used elsewhere. In the same pass: every client's item picker was pulling from every org's catalog regardless of context, leaking Premier U's taxonomy into Studio Strong clients' screens; fixed with real org-scoped write and visibility restrictions for non-admin trainers.
SecurityFull PIN system for clients and trainers
Clients get a one-time device check using the last 4 digits of their own phone number, with a self-serve "change my PIN" option and a graceful "text your trainer" fallback after repeated wrong attempts — no email system, no separate password to lose. Trainers get their own first-time PIN setup, and the gate was extended to cover every admin page consistently after finding plan.html and library.html only checked token validity, not the PIN itself — a real bypass of the front door.
